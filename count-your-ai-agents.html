Count your AI agents before you try to govern them

Metanous, November 12, 2026

Most companies can tell you how many employees they have. Few can tell you how many AI agents are acting in their name.

Microsoft built Agent 365 around that gap. It became generally available for commercial customers on May 1, 2026. Whether or not you buy it, the questions it raises are worth answering now.

What Microsoft is offering

Agent 365 is a control layer for AI agents. Microsoft organizes it around three verbs:

  • Observe. One registry of the agents in your organization, in the Microsoft 365 admin center, with their adoption, activity and health.
  • Govern. Lifecycle management, access control and compliance, handled through the registry, Microsoft Entra and Microsoft Purview.
  • Secure. Entra's risk-based access controls, Purview's data protection, and Microsoft Defender's threat detection, extended to agents.

It is licensed per user. Microsoft says it works best with Microsoft E5, and at least one user must hold a qualifying Agent 365 license to switch it on.

The tool is the easy part

A registry only helps if you know what belongs in it. Before you configure anything, answer four questions:

  1. Which agents exist? Include the ones a team built on its own, not only the ones IT approved.
  2. Who owns each one? A named person, who answers when the agent does something odd.
  3. What can it reach? Give each agent the access its job needs and nothing more.
  4. What happens when it is retired? An agent nobody switches off keeps its access.

If you cannot answer these on a spreadsheet, a control panel will not answer them for you.

Clean up your data first

Microsoft describes agents acting on behalf of users, under the same access controls. That makes an agent only as careful as the permissions behind it.

A folder shared with everyone for years is a small risk while nobody searches it. Give an agent the same reach and it can find and repeat what is in there in seconds. Fixing over-shared sites and labeling sensitive files comes before any agent policy. It is dull work, and it does the most to reduce risk.

A sensible order of work

  1. Turn on visibility first and see what is actually running.
  2. Name an owner for every agent you find.
  3. Fix access on the data those agents can touch.
  4. Write your rules last, based on what you saw.

Features differ by plan, so check Microsoft's service description before you commit.

Source: Microsoft Learn, Microsoft Agent 365 overview. The advice sections are Metanous's opinion.
